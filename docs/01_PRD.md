# 카페 판매·손익·재고 관리 제품 요구사항 문서

작성일: 2026-10-12  
상태: 1차 제품 요구사항 정리 완료. 2026-10-12 사용자의 “모두 추천대로” 지시에 따라 남은 기획 결정에 추천안을 적용했다. 자료 사실과 채택한 운영 원칙, 후속 단계에서 정할 사항을 구분한다.  
MVP: 처음 만들어 실제로 핵심 업무를 해볼 수 있는 최소 기능 범위.

## 1. 제품의 목적

카페 운영자가 판매 기록을 입력한 뒤 메뉴별로 얼마나 남는지 살펴보고, 같은 기록을 바탕으로 기간별 손익과 재료 잔량을 확인하는 웹 프로그램이다. 기록을 고치거나 지웠을 때도 관련 결과가 일관되게 바뀌어야 한다.

사용자가 요청한 전체 목표는 판매·비용 직접 입력·수정·삭제, 엑셀 양식 다운로드와 기록 가져오기, 재료 입고·폐기·실제 재고 기록, 부족 재료와 참고 발주량 확인, 기간별 실적과 예상 손익, 저장·백업·복원이다. 조회 기간은 일·주·월·분기·반기·연간이다.

이 문서는 목적, 기능 우선순위, 성공 조건만 다룬다. 계산식, 화면 디자인, 기술 선택, 상세 조작 방식, 코드는 후속 단계에서 정한다.

## 2. 자료에서 확인한 사실

검토 자료: 실습 폴더의 `데이터설명.md`, `매장운영데이터.xlsx`, `매장운영데이터.json`.

- 프렙 카페의 가상 샘플이다. 실제 거래나 실제 재고를 증명하는 자료가 아니다.
- 판매·비용 기록 기간은 2025-07-01부터 2026-09-18까지다. 영업달력은 2026-09-30까지 있다.
- 금액은 원, 부가세 제외다. 재료 단위는 g·ml·개다.
- 엑셀과 JSON은 같은 기록의 두 형식으로 제공된다. 각각의 기록 수와 주요 항목을 확인했다. 날짜는 엑셀의 날짜 값과 JSON의 문자열처럼 형식이 다르므로 가져올 때 같은 날짜로 해석해야 한다.
- 엑셀에는 안내용 `데이터안내` 시트가 별도로 있다. JSON에는 출처·기간 정보인 `meta`가 있고 `settings`는 비어 있다. 운영 정책이 이미 설정된 자료가 아니다.

| 기록 | 수 | 확인한 내용 |
| --- | ---: | --- |
| 공급사 | 3 | 공급사 식별번호·이름 |
| 재료 | 11 | 단위, 구매용량, 최초가격, 공급사, 납기·안전재고 영업일 수 |
| 메뉴 | 8 | 메뉴명, 판매기준가, 음료·디저트 분류, 레시피버전 |
| 레시피 | 22 | 메뉴 1개에 필요한 재료량, 포장 채널에만 쓰는 포장재 |
| 재료가격이력 | 33 | 적용시작일, 구매용량 전체의 가격 |
| 영업달력 | 457 | 영업·휴무, 마감 여부, 날씨, 메모 |
| 판매기록 | 6,112 | 날짜·메뉴·매장/포장별 수량, 당시단가, 할인, 순매출, 수수료, 개당 원가 |
| 초기재고 | 11 | 2025-07-01 영업 시작 전 재료 수량 |
| 재고기록 | 1,515 | 입고 1,302건, 폐기 189건, 실사조정 24건 |
| 월비용계획 | 120 | 월별 8개 비용항목과 금액 |
| 비용기록 | 3,560 | 월비용을 날짜별로 나눈 비용, 날짜·금액·배분기준 |
| 자료정보 | 10 | 매장명, 출처, 통화, 시작일·마감일 등 |

비용항목은 임차료, 인건비, 사업주 부담 보험료, 수도광열비, 관리비, 통신·소프트웨어, 광고비, 소모품·청소비다. 판매기록은 주문 한 건씩의 내역이 아니라 하루의 메뉴·채널별 합계다. 판매 식별번호와 날짜·메뉴·채널 조합은 제공된 JSON에서 중복이 없다.

## 3. 기획할 때 주의할 점

| 자료의 특징 | 요구사항에 미치는 영향 |
| --- | --- |
| 엑셀·JSON이 같은 자료다 | 둘을 모두 더해 이중 집계하지 않는다. 초기 자료는 한 번만 반영한다. |
| 월비용계획과 날짜별 비용은 같은 비용이다 | 별도의 지출 두 개로 취급하지 않는다. 실적과 계획의 용도를 구분해야 한다. |
| 날짜별 비용은 모두 월비용 일할 배분 기록이다 | 실제 결제일의 지출이나 통장 잔액으로 표현하지 않는다. 새 비용도 해당 기간 기준으로 기록하기로 합의했다. 날짜별 배분 방법은 미정이다. |
| 과거의 단가·원가·수수료가 저장돼 있다 | 당시 기록을 보존한다. 새 판매도 판매일의 가격·레시피와 해당 판매의 수수료를 근거로 기록한다. 산정 방법은 후속 단계에서 정한다. |
| 개당 원가와 판매 전체 금액이 함께 있다 | 서로의 의미를 혼동하지 않는다. 메뉴 수익성과 매장 전체 손익의 의미도 구분한다. |
| 레시피에 채널별 포장재가 있다 | 매장 판매와 포장 판매에서 사용하는 재료가 다름을 반영한다. |
| 재고기록은 입고·폐기·실사조정이다 | 판매에 따른 재료 사용도 잔량 확인에 연결해야 한다. 판매 수정을 재고에 중복 반영하지 않는다. |
| 실사조정에는 증감량과 실제 센 수량이 있다 | 장부상 잔량과 실제로 센 재고를 구분한다. 같은 실사를 두 번 반영하지 않는다. |
| 미래 영업일에 마감 표시가 없다 | 미마감·미입력을 판매 0인 날로 처리하지 않는다. 기록이 없는 기간과 실제 0인 기간을 구분한다. |
| 연간 자료가 일부 기간만 포함한다 | 조회 기간과 자료가 있는 기간을 알 수 있어야 한다. 불완전한 연간 합계를 완전한 연간 실적으로 표현하지 않는다. |
| 빈칸은 해당 없음 또는 미입력이다 | 빈칸을 임의로 0으로 채워 수익·재고가 정상인 것처럼 보이게 하지 않는다. |
| 납기·안전재고 일수는 영업일 기준이다 | 1차는 남은 재료가 없거나 장부 잔량이 음수인 경우를 확인한다. 미리 부족을 예상하거나 발주량을 추천하는 기능은 2차로 둔다. |

## 4. 핵심 사용자와 흐름

주 사용자는 카페 판매·비용·재고 기록을 관리하는 운영자다. 1차는 한 매장·운영자 1명·주 사용 기기 1대의 컴퓨터에서 사용하는 범위로 한다. 여러 기기 간 동기화와 여러 사람의 동시 사용은 1차에 포함하지 않는다. 이는 채택한 제품 범위이며 사용자의 실제 기기나 운영 상황을 자료에서 확인한 사실은 아니다.

1. 운영자가 하루의 메뉴·채널별 판매 기록을 입력한다.
2. 기록이 메뉴 수익성에 반영돼 어떤 메뉴에서 얼마나 남는지 확인한다.
3. 같은 기간의 비용을 함께 확인해 매장 손익을 살펴본다.
4. 판매에 쓰인 재료와 입고·폐기·실사 기록을 통해 잔량을 확인한다.
5. 잘못된 기록을 수정·삭제한 뒤 관련 결과가 함께 바뀌는지 확인한다.
6. 작업한 기록을 저장하고, 백업과 복원으로 다시 사용할 수 있다.

예: 오늘 카페라떼 포장 판매를 입력한 뒤 카페라떼의 수익성을 확인하고, 오늘의 매장 손익과 우유·원두·포장컵 잔량을 이어서 확인한다. 이 예시는 업무 흐름이며 숫자나 판단 기준을 확정하지 않는다.

## 5. 합의한 1차 구현: 4시간 MVP

2026-10-12 사용자 답변으로 핵심 흐름에 집중하는 A 범위를 합의했다. 판매·비용 기록 입력·수정·삭제, 메뉴 수익성, 기록된 손익, 재고 기록·잔량, 일·월 조회, 기본 저장·백업·복원을 1차에 포함한다. 엑셀 양식·가져오기, 주·분기·반기·연간 조회, 예상 손익·발주량 추천은 2차로 둔다. 이어진 “모두 추천대로” 지시에 따라 운영 원칙도 제8절과 같이 정리했다.

| 핵심 기능 | 1차에서 제공할 가치 | 합의 범위와 남은 결정 |
| --- | --- | --- |
| 제공 자료로 시작 | 기존 판매·비용·재고와 메뉴·재료를 확인한다 | 한 매장, 제공 메뉴 8개·재료 11개를 기준으로 시작한다. 새 메뉴·레시피 관리 도구는 제외한다. |
| 판매 기록 관리 | 날짜·메뉴·채널별 판매를 입력·수정·삭제한다 | 주문별 내역, 결제 연동, 쿠폰 관리는 제외한다. 판매 당시 기준을 보존하며 잘못된 입력은 수정할 수 있다. 새 판매의 근거는 제8절을 따른다. |
| 비용 기록 관리 | 손익에 필요한 비용을 입력·수정·삭제한다 | 비용이 해당하는 기간 기준으로 기록한다. 기존 배분 비용과 중복 집계하지 않는다. 날짜별 배분 방법은 미정이며 자동 월비용 배분 도구는 제외한다. |
| 메뉴 수익성 확인 | 선택 기간에 메뉴별로 얼마나 남는지 비교한다 | 합의한 A 기준: 재료·포장·결제수수료 등 판매에 직접 드는 비용을 반영한다. 임차료·인건비는 메뉴별로 나누지 않고 매장 전체 손익에서 확인한다. 좋음·나쁨 등 자동 등급은 제외한다. |
| 기간 실적·손익 | 기록된 매출·비용과 손익을 확인한다 | 1차는 일·월 조회를 제공한다. 예상 손익과 나머지 기간 조회는 2차로 둔다. |
| 재고 기록·잔량 | 입고·폐기·실제 센 재고를 기록하고 판매에 따른 잔량을 확인한다 | 실제 센 수량을 해당 시점의 재고 기준으로 삼는다. 남은 재료가 없거나 장부 잔량이 음수인 경우를 알 수 있다. 음수는 기록 점검이 필요한 상태로 구분한다. 발주량 추천은 제외한다. |
| 기본 저장·백업·복원 | 다시 열어도 기록을 유지하고 백업한 기록을 복원한다 | 한 매장의 기록 전체와 결과 확인에 필요한 기준 자료를 함께 백업·복원한다. 사용자가 백업본을 별도로 보관할 수 있어야 한다. 저장 위치·형식·복원 상세 방식은 후속 단계에서 정한다. 자동 정기 백업은 제외한다. |

### 4시간 작업 배분 제안

| 단계 | 시간 | 이 단계의 결과 |
| --- | ---: | --- |
| 기획 | 25분 | 핵심 지표의 의미, 비용·재고 기준, 1차 범위 합의 |
| 화면 설계 | 20분 | 핵심 업무 흐름에 필요한 구성 정리 |
| 개발 | 115분 | 입력·결과 확인·보관 기능 연결 |
| 검사 | 50분 | 핵심 흐름, 수정·삭제 반영, 데이터 중복, 저장·복원 확인 |
| 배포 | 30분 | 합의한 사용 환경에서 실행·재접속 확인 |
| 합계 | 240분 | 첫 사용이 가능한 핵심 기능 |

이는 작업 목표이며 완료 보장이 아니다. 제품 사용 범위는 컴퓨터 1대·운영자 1명으로 정했다. 구체적인 실행 환경과 계산식은 후속 단계에서 정하고 구현 전 추정을 다시 확인한다. 새로운 로그인·다중 사용자 기능이나 외부 서비스 연결은 이 시간 계획에 포함하지 않는다. 배포 완료는 주 사용 환경에서 실행하고 다시 접속해 사용할 수 있는 상태를 뜻한다. 이번 문서에서는 화면과 기술을 선택하지 않는다.

시간이 부족하면 확장 기능을 추가하지 않고 입력 → 메뉴 수익성 → 손익·잔량 흐름과 검사·저장·복원을 우선한다. 핵심 기능을 더 줄여야 할 경우 범위 변경을 사용자와 합의한다.

## 6. 2차 구현 제안

| 확장 기능 | 필요한 이유·1차에서 미루는 이유 |
| --- | --- |
| 엑셀 양식 다운로드·기록 가져오기 | 반복 입력을 줄인다. 중복 기록, 잘못된 단위·날짜, 기존 기록과의 충돌 처리까지 검사가 필요해 1차 핵심 흐름 이후로 제안한다. |
| 주·분기·반기·연간 조회 | 사용자가 원하는 전체 기간 조회를 완성한다. 주의 시작일 등 기간 기준을 먼저 합의한다. |
| 예상 손익 | 남은 기간의 매출·비용을 예상한다. 예상 대상 기간과 근거를 선택해야 하며 실적과 구분해야 한다. |
| 부족 재료 판단 확장·참고 발주량 | 납기·안전재고·구매용량을 참고해 주문 판단을 돕는다. 수요 예상과 부족 기준이 필요하다. 자동 주문은 포함하지 않는다. |
| 메뉴·재료·레시피·가격 관리 | 실제 매장의 변화에 대응한다. 변경 전후의 기록을 보존할 기준이 필요하다. |
| 월비용 계획 관리·자동 배분 | 비용 입력을 줄이고 계획과 실적을 비교한다. 새 비용과 기존 배분 비용의 중복 방지 기준이 필요하다. |
| 보관 기능 확장 | 정기 백업, 여러 백업 시점의 관리 등 복구 편의를 높인다. |

엑셀 양식·가져오기, 나머지 기간 조회, 예상 손익·발주량 추천은 2차로 분리하기로 합의했다. 추천 우선순위는 엑셀 기록 가져오기 → 조회 기간 확대 → 예상 손익 → 부족 예상·발주량 참고다. 나머지는 추가 확장 후보로 유지한다. 2차 일정과 상세 기준은 후속 단계에서 정한다. 이후 1차 범위를 바꾸려면 사용자와 합의한다.

## 7. 1차 구현 성공 조건

아래는 확인할 결과이며 상세 검사 방법이나 계산식은 후속 단계에서 정한다.

- 제공 기록이 한 번만 반영되고, 자료 기간·가상 샘플임을 확인할 수 있다.
- 판매 한 건을 입력한 뒤 해당 메뉴 수익성, 같은 기간 손익, 관련 재료 잔량을 이어서 확인할 수 있다.
- 판매를 수정·삭제하면 합의한 기준에 따라 관련 결과가 일관되게 바뀌고 재료 사용이 중복 반영되지 않는다.
- 비용을 입력·수정·삭제하면 같은 기간 손익에 반영되며 월비용계획을 별도 지출로 이중 반영하지 않는다.
- 입고·폐기·실제 센 재고를 기록할 수 있고 장부상 잔량과 실측 기록을 구분할 수 있다.
- 재료 가격이 바뀌어도 과거 실적이 자동으로 바뀌지 않는다. 잘못 입력한 과거 기록은 수정할 수 있다.
- 실제로 센 재고를 해당 시점의 기준으로 사용할 수 있고, 소진 상태와 음수 잔량을 확인할 수 있다.
- 일·월 조회에서 자료가 일부만 있는 기간과 미마감 상태를 알 수 있다.
- 필수 기록이 빠졌을 때 결과를 확정값처럼 제시하지 않는다.
- 저장 후 다시 사용해도 변경 기록이 유지된다. 백업 시점의 기록과 핵심 결과를 복원할 수 있다.
- 합의한 사용 환경에서 핵심 흐름을 실행할 수 있다.

## 8. 추천안으로 채택한 운영 원칙

2026-10-12 사용자가 “모두 추천대로 해줘”라고 요청했다. 아래는 자료에서 발견한 정책이 아니라 이 지시에 따라 채택한 기획 권고안이다. 기존에 확정한 메뉴 수익성, 1차 범위, 비용 기록의 의미도 유지한다.

| 결정 | 채택한 추천안 | 쉬운 예시와 이유 |
| --- | --- | --- |
| 메뉴 수익성 | 판매에 직접 드는 재료·포장·결제수수료 등을 반영한다. 임차료·인건비는 매장 전체 손익에서 확인한다. | 라떼 자체에서 남는 금액을 비교하고, 매장 전체로도 이익인지 확인한다. 메뉴별 매장 비용 배분을 줄인다. |
| 비용의 의미 | 비용이 해당하는 기간에 기록한다. | 9월 월세를 10월에 결제해도 9월 비용이다. 같은 기간의 판매와 비교하기 좋다. |
| 과거 기록 보존 | 당시 단가·원가·수수료·레시피 근거를 유지한다. 잘못된 입력은 수정할 수 있다. | 오늘 우유 가격이 올라도 지난달 라떼 실적은 그대로다. 가격 변경과 입력 오류 수정을 구분한다. |
| 새 판매의 근거 | 판매일에 적용되는 재료 가격·레시피와 해당 판매의 실제 단가·할인·결제수수료를 근거로 한다. 근거가 없는 값은 확정 결과처럼 표시하지 않는다. | 오늘의 라떼를 오래된 원가로 평가하거나 수수료 미입력을 0으로 취급하는 일을 피한다. 계산식·자동 산정 방식은 별도로 정한다. |
| 실제 센 재고 | 실제 센 수량을 해당 시점의 재고 기준으로 삼고 이후 변동과 연결한다. 이전 기록과 장부 잔량의 차이는 확인할 수 있어야 한다. | 장부에 우유 3L가 남았지만 실제로 2L를 셌다면 그 시점부터 2L를 기준으로 본다. 같은 실사를 중복 반영하지 않는다. |
| 1차 부족 확인 | 남은 재료가 없거나 장부 잔량이 음수인 경우를 알 수 있게 한다. 음수는 기록 점검이 필요한 상태로 구분한다. | 원두가 소진된 상황을 확인한다. 음수는 실제 재료량으로 믿기보다 누락·오류를 점검한다. 며칠 뒤 부족할지 예상하는 기능은 2차로 둔다. |
| 사용 범위 | 한 매장·운영자 1명·주 사용 컴퓨터 1대에 집중한다. | 매장 컴퓨터에서 기록하고 다시 열어 이어서 사용한다. 여러 기기 동기화·동시 사용은 1차에서 제외한다. |
| 백업·복원 범위 | 매장 기록 전체와 결과 확인에 필요한 메뉴·재료·레시피·가격 등 기준 자료를 함께 보관·복원한다. | 판매 기록만 복원해 원가나 재고를 확인할 수 없게 되는 일을 방지한다. 부분 복원·여러 자료 합치기는 1차에서 제외한다. |
| 2차 우선순위 | 엑셀 기록 가져오기, 조회 기간 확대, 예상 손익, 부족 예상·발주량 참고 순으로 진행한다. | 반복 입력을 줄이는 기능부터 확장한다. 나머지 제6절 기능은 추가 후보로 유지한다. |

## 9. 후속 단계에서 정할 사항

PRD의 핵심 범위와 운영 원칙은 정리했다. 다음 항목은 사용자의 최초 요청에 따라 이번 문서에서 정하지 않는다. 추천안 채택을 상세 설계까지 합의한 것으로 해석하지 않는다.

| 항목 | 현재 상태 |
| --- | --- |
| 계산식·산정 세부 기준 | 일별 비용 반영, 원가·수수료 산정, 반올림, 재고 변동 처리 등의 정확한 방법은 후속 단계에서 정한다. 기존 일별 비용을 수정 없이 확인하는 것과 새 비용 처리의 의미를 구분한다. |
| 화면 디자인 | 화면 구성·배치·모양은 화면 설계 단계에서 정한다. |
| 기술·실행 환경 | 구현 기술, 저장 위치·방식, 백업 형식, 배포 수단은 후속 단계에서 정한다. |
| 상세 동작 | 입력 항목의 세부 규칙, 수정·삭제·복원 절차, 같은 날 판매·실사의 순서 등은 후속 단계에서 정한다. |
| 2차 설계·일정 | 전망 방법, 발주량 기준, 주·분기 등 기간 경계, 엑셀 가져오기 충돌 처리와 개발 일정은 2차 기획에서 정한다. |
