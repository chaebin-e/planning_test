# 카페 판매·손익·재고 관리 기능 요구사항 문서

작성일: 2026-10-12  
상태: 검토용 초안. PRD에서 확정한 기능 범위와 운영 원칙은 유지한다. 계산식·상세 동작·시안 수정은 제안이며 사용자 확인 전까지 확정하지 않는다.  
FRD는 사용자가 하는 일, 프로그램이 처리하는 일, 화면·파일 결과, 실패했을 때의 동작을 설명하는 문서다.

## 1. 제품과 읽는 방법

한 매장·운영자 1명이 컴퓨터 1대에서 사용하는 프로그램이다. 하루의 메뉴·매장/포장별 판매를 직접 입력하고, 메뉴별 수익성 → 같은 기간 매장 손익 → 재료 잔량을 확인한다. 비용은 실제 결제일보다 해당하는 기간에 기록한다. 재료 입고·폐기·실제 센 재고를 기록하고 저장·백업·복원한다.

이 문서만 읽어도 1차 기능과 제안 동작을 알 수 있도록 작성했다. 단, 미정 항목을 구현자가 임의로 선택해서는 안 된다.

- **확정:** PRD에 합의된 목적·범위·운영 원칙.
- **시안 확인:** 화면 이미지나 HTML에 존재하는 표시·입력칸·버튼. 작동을 보장한다는 뜻은 아니다.
- **제안:** 해당 기능을 완성하기 위한 계산·처리·오류 대응 권고안. 아직 미확정이다.
- **미정/불일치:** 사용자 선택이 필요한 부분. 관련 결과를 확정값으로 만들거나 새 기능을 추가하지 않는다.

자료: `docs/01_PRD.md`, `design/warm_cafe_operations/DESIGN.md`, `design/_1`~`design/_4`의 `screen.png`와 `code.html`. 원본 기록의 의미는 실습 폴더의 `데이터설명.md`와 기존 PRD 검토 결과를 따른다. PRD·시안·원본 자료는 이 작업에서 수정하지 않았다.

## 4. 함께 적용할 동작 제안

아래의 세부 동작은 전부 제안이다. 기존 필수 기능을 안전하고 일관되게 제공하기 위한 내용이며 새 업무 기능을 승인한 것은 아니다.

## 5. 기능별 사용자 행동과 처리

### F01. 제공 자료로 시작

**확정:** 프렙 카페 가상 자료로 시작한다. 기록은 2025-07-01~2026-09-18, 영업달력은 2026-09-30까지다. 금액은 부가세 제외 원, 재료 단위는 g·ml·개다. 판매 6,112건·재고 변동 1,515건·비용 3,560건이다. 판매는 주문별이 아니라 일자·메뉴·채널별 합계다.

**사용자/처리 제안:** 처음 열 때 제공 자료의 한 형식만 한 번 읽어 메뉴·재료·기존 기록을 준비한다. 이미 저장된 자료가 있으면 그것을 먼저 사용한다. 각 기록의 식별번호를 유지하고 연결된 메뉴·재료·레시피가 있는지 확인한다.

**화면:** 가상 자료임과 기록 범위를 알 수 있다. 화면 예시 값을 실제 집계에 섞지 않는다. **파일:** 초기 설정만으로 사용자 다운로드 파일을 생성하지 않는다. 앱 보관 자료와 원본 파일은 구분한다.

**예외:** 손상된 초기 자료, 없는 메뉴/재료 참조, 중복 식별번호, 날짜·단위 해석 실패는 대상과 이유를 알리고 정상 준비 완료로 표시하지 않는 안을 추천한다. 문제 자료를 임의로 누락한 채 전체 결과라고 표시하지 않는다.

### F02. 일·월 조회와 화면 이동

**사용자:** 네 화면의 메뉴를 누르거나 일간/월간과 날짜·월을 선택한다. **처리 제안:** 일간은 선택 날짜, 월간은 선택 월에 해당하는 기록을 묶는다. 달력상 월 전체 조회 범위와 실제 기록이 있는 구간을 따로 표시한다. 월 중간 실적을 월말 예상으로 늘리지 않는다.

**화면:** 판매·비용 목록, 메뉴 수익성, 매장 손익을 선택 기간으로 표시한다. 재고는 그 기간의 변동과 조회 기준일의 잔량을 구분한다. 월 잔량을 일별 잔량 합계로 표현하지 않는다. **파일:** 조회·정렬·검색만으로 파일은 생성하지 않는다.

**예외 제안:** 잘못된 날짜는 재선택 요청. 자료 시작 전 재고는 계산 근거 없음. 기록 없는 날짜는 '자료 없음', 미마감은 '미마감', 완료된 휴무일은 해당 상태를 표시한다. 마감된 날짜의 확인된 0과 미입력은 구분한다. 선택 범위가 자료보다 넓으면 실제 포함 기간을 안내한다. 새 날짜의 마감 판단은 Q04 미정이다.

시안의 매출액순·공헌마진 합계순 정렬, 재료 검색·상태 필터는 현재 결과를 찾아보는 표시 동작으로 검토한다. 정렬은 기록을 바꾸지 않으며 같은 값은 식별번호 등 일정한 순서로 표시하는 안을 추천한다. 별도의 시간 기록 기능은 추가하지 않는다.

### F03. 판매 기록 입력·수정·삭제

**사용자:** '판매 내역 기록' 또는 기존 행의 수정 버튼을 누른다. 시안 칸은 판매일·메뉴·매장/포장·수량·기본 단가·총 할인액이다. 입력 후 '판매 기록 저장'을 누른다.

**처리 제안:** 날짜·메뉴·채널·수량을 확인하고 실제 단가·전체 할인액·실제 수수료 및 판매일의 가격·레시피 근거로 C01~C04를 계산한다. 미리보기는 저장 전 임시 결과다. 저장 후 한 개의 판매 기록으로 보관하고 F05·F06·F08을 함께 갱신한다. 수수료 입력 수단과 실제 단가 편집은 D04·D08·Q02에서 결정해야 한다.

**화면:** 날짜·메뉴·채널·수량·당시 단가·순매출·재료/포장 원가·수수료·남는 금액을 확인한다. 저장 전 미리보기와 저장 완료를 구분한다. **파일:** 앱 기록에 판매 식별번호·입력값·당시 원가·레시피 근거를 보관하는 안을 추천한다. 별도 판매 보고서는 만들지 않는다.

**수정:** 수량·할인·수수료만 바꾸면 당시 원가 근거를 유지해 다시 계산한다. 메뉴·날짜·채널이 바뀌면 그 변경에 맞는 당시 기준이 필요하다. 재선정 규칙은 Q03 미정이다. 기존 기록을 새 기록으로 더하지 않는다. 재고는 변경 전·후 판매를 통틀어 다시 계산해 중복 사용을 막는다.

**삭제:** 행 삭제 또는 '이 기록 삭제'에서 확인 후 대상 판매를 제거하고 연결 결과를 다시 계산하는 안을 추천한다. 실사 이전 판매 삭제가 현재 재고를 그대로 증가시키는 것은 아니다. 실측 시점이 있으면 C09의 기준을 적용한다.

**오류·예외 제안:**

- 수량은 양의 정수, 단가·할인·수수료는 0 이상으로 제한한다. '15.5잔', 음수 수량·금액, 숫자가 아닌 문자는 저장하지 않는다. 0수량·반품 기능은 새로 추가하지 않는다.
- 할인액이 할인 전 판매금액보다 크면 저장하지 않는다. 할인으로 순매출 0이 되는 경우는 0매출로 남기되 이익률을 계산 불가로 표시하는 안을 추천한다.
- 수수료가 순매출보다 크면 입력 확인을 요청한다. 허용 여부는 Q02에서 함께 결정한다.
- 같은 날짜·메뉴·채널이 이미 있으면 기존 행 수정을 안내하고 새 중복 행 저장을 막는 안을 추천한다. 자동 합산/덮어쓰기 여부는 Q05 미정이다.
- 미래 판매일은 실적 입력과 혼동되므로 저장을 막는 안을 추천한다. 휴무일 입력은 달력 확인을 요청한다. 새 날짜 허용 조건은 Q04에서 결정한다.
- 가격·레시피·수수료 근거가 없으면 확정 수익을 보여주지 않는다. 현재 가격으로 과거를 대신 평가하지 않는다.
- 저장 직후 다시 저장하거나 새로고침해도 동일 판매와 사용량이 두 번 반영되지 않는다.

### F04. 비용 기록 입력·수정·삭제

**확정:** 비용은 해당하는 기간에 기록한다. 월비용계획과 일별 비용기록은 같은 비용이므로 함께 더하지 않는다. 초기 일별 비용은 실제 결제 내역이 아니라 월비용을 나눈 기록이다.

**사용자:** '일일 비용 등록' 또는 비용 등록 버튼을 누르고 금액을 기록한다. 기존 비용을 수정·삭제할 수 있어야 한다. 해당 조작 수단은 시안에서 빠져 있다.

**처리 추천안:** 1차는 귀속일·기존 8개 비용항목·금액을 직접 관리한다. 기존 비용은 원래 기록을 유지한다. 월세를 날짜별로 나누어 입력해야 한다면 이미 배분한 금액을 사용자가 기록하며 프로그램의 월 자동 배분 기능을 추가하지 않는다. 시안의 귀속월·월 총액·배분 라디오를 그대로 적용할지는 D02·Q06에서 확인한다.

**화면:** 날짜·항목·금액을 비용 목록과 F06에 표시한다. 해당 월에 발생한 비용과 실제 결제일 지출을 혼동하지 않는다. **파일:** 앱에 귀속일·항목·금액·비용 식별번호와 기존 배분 출처를 보관하는 안을 추천한다. 월계획 자체는 F06의 실적 비용에 합하지 않는다.

**오류·예외 제안:** 빈 날짜·항목·금액, 음수·잘못된 금액은 저장하지 않는다. 0원은 명시적으로 입력한 경우만 허용하는 안을 추천한다. 같은 날짜·항목의 기존 비용이 있으면 먼저 보여주고 추가와 수정을 구분한다. 여러 실제 비용이 있을 수 있어 판매처럼 무조건 중복으로 금지하지 않는다. 동일 지출의 중복 여부는 사용자가 확인해야 한다. 날짜를 바꾸면 이전·새 기간 모두 재계산한다. 저장 실패·삭제 취소는 기존 결과를 유지한다. 기타 항목 신설은 승인하지 않는다.

### F05. 메뉴 수익성 확인

**사용자:** 메뉴 수익성 화면에서 날짜·월을 선택하고 메뉴 행을 누른다. **처리 제안:** 판매당 C04 결과를 C05로 모아 메뉴별 순매출·수량·원가·수수료·남는 금액을 보여준다. 매장/포장 구분은 실제 채널을 사용하며 HOT/ICE 메뉴를 새로 만들지 않는다.

**화면:** 메뉴별 합계와 전체 합계, 수익률·판매 1개당 평균 금액은 계산 제안 승인 후 표시한다. 열 제목은 '전체 금액'과 '1개당 평균'을 구분한다. 선택 메뉴에서는 해당 기간에 적용된 레시피·원가 근거를 확인한다. 같은 기간에 가격이 여러 번 바뀌면 한 단가가 전 기간에 적용된 것처럼 보여주지 않는다.

개당 원가 기록만으로 과거 재료별 원가 구성까지 확정할 수 없는 경우 '재료별 상세 근거 없음'으로 표시하는 안을 추천한다. 시안의 구성 비중을 사실처럼 복사하지 않는다. 정렬·메뉴 선택·기준 안내는 보관된 기록을 바꾸지 않는다. **파일:** 1차에는 '원가 보고서 출력' 다운로드를 추가하지 않는다. 출력 버튼 처리 자체는 D11 미정이다.

**예외:** 판매 없음은 '판매 기록 없음', 순매출 0은 이익률 계산 불가. 누락 원가·수수료가 있으면 해당 메뉴와 전체 이익을 미확정으로 표시한다. 누락 행을 제외한 소계는 '확인된 기록만의 소계'로 표시하고 전체 결과로 제시하지 않는다. 서로 단위가 다른 g·ml·개는 합산하지 않는다. 평균은 개당 값을 단순 평균하지 않는다.

### F06. 기간 실적·매장 손익

**사용자:** 매장 손익 화면에서 일·월을 선택하고 상세 내역을 확인한다. **처리 제안:** C06으로 순매출·판매 사용 재료/포장 원가·결제수수료·해당 기간 비용·매장 손익을 계산한다. 메뉴 공헌이익에서 기간 비용을 반영하며 월세·인건비를 메뉴별로 배분하지 않는다.

**화면:** 합계와 판매채널·비용항목별 내역을 같은 기준으로 보여준다. '전체 펼치기'는 세부 내역 표시만 바꾸는 안을 추천한다. '고정비만 보기'는 모든 비용항목을 고정비로 단정할 수 없어 항목 분류와 적용 여부를 확인해야 한다. 전망, 손익분기점, 목표·전년 비교는 미승인으로 유지한다. **파일:** 1차 손익 엑셀 출력은 추가하지 않는다. 백업 파일은 F10에서 따로 다룬다.

**예외:** 판매 기록이 있어도 미마감이면 잠정 실적으로 구분한다. 비용 입력 완료 여부를 알 수 없다면 '입력된 기록 기준'임을 표시하고 미입력 비용을 0으로 확정하지 않는다. 원가·수수료가 누락되면 순매출처럼 확인된 값은 보여주고 손익은 미확정으로 표시한다. 9월 18일까지만 기록됐으면 19~30일을 0이나 자동 전망으로 채우지 않는다.

폐기·실사 손실을 비용으로 반영하는 방법은 Q08 미정이다. C06 기본안은 판매 기록 원가와 기간 비용만 사용한다. 따라서 Q08 결정 전에는 이것이 폐기까지 포함한 최종 손익이라고 표시하지 않는다.

### F07. 입고·폐기·실제 재고 기록

**사용자:** '재고 변동 기록 등록' 또는 재료 행의 '조정/입고·입고 등록'을 누른다. 입고·폐기·실사 탭을 선택하고 날짜·재료·수량을 기록한다. 행에서 열면 해당 재료를 미리 선택하는 안을 추천한다.

**입고 제안:** 입고 수량을 양수로 입력하면 같은 단위로 증가시킨다. 공급사는 기존 식별번호와 연결할 수 있도록 보완한다. 자유 입력 공급사명을 기존 공급사로 자동 합치지 않는다. 공급사명·사유의 필수 여부와 입고 단위원가 입력 필요 여부는 Q08·Q09 미정이다.

**폐기 제안:** 폐기한 양을 양수로 입력받고 감소 기록으로 보관한다. 입력칸에 음수를 다시 넣어 재고가 증가하지 않게 한다. 사유를 함께 기록한다. 폐기 금액과 손익 반영은 수량 기록과 별도 결정이다.

**실사 제안:** 실제 센 수량을 0 이상으로 입력받는다. '증감 수량'이 아닌 '실제 센 수량'으로 칸 뜻을 바꾸어 안내한다. 해당 시점의 장부 수량과 비교해 C09의 차이를 확인하고 실측량을 기준으로 삼는다. 같은 실사를 실측량과 증감량으로 두 번 반영하지 않는다.

**화면:** 저장 후 해당 재료 잔량·최근 실측일/수량·차이를 갱신한다. 현재 장부 잔량과 오래된 실측량을 단순 비교해 '실사 오차'라고 부르지 않는다. 실측 당시의 차이와 이후 변동을 구분한다. **파일:** 재료·유형·일자·단위·수량·사유·실측 근거를 앱에 보관하는 안을 추천한다. 원본 기록을 변경하지 않는다.

**예외 제안:** 입고·폐기는 0보다 큰 양, 실사는 0도 허용한다. '개'는 정수, g·ml의 허용 소수 자릿수는 Q09에서 결정한다. 단위는 재료 기준단위로 고정하며 L→ml 같은 새 변환 기능은 추가하지 않는다. 없는 재료·잘못된 단위·미래 기록은 저장하지 않는 안을 추천한다. 폐기 후 음수 잔량은 조용히 0으로 바꾸지 않고 점검 상태로 보여준다. 폐기 저장을 허용할지는 Q09 미정이다. 시안에 없는 재고기록 수정·삭제 도구는 새 기능으로 추가하지 않는다.

### F08. 잔량·소진·음수 확인

**사용자:** 재고 화면을 열고 재료명 검색 또는 상태 필터를 사용한다. **처리 제안:** 초기재고·판매 사용량·입고·폐기·실사에 C08~C09를 적용해 기준일 잔량을 계산한다. 자료에 없는 메뉴 재료를 추측해 차감하지 않는다.

**화면:** 재료별 이름·기준단위·장부 잔량·최근 실측 기준·실측 당시 차이·상태를 표시한다. 잔량 양수는 '잔량 있음', 0은 '소진', 음수는 '기록 점검 필요'다. '잔량 있음'이 앞으로 충분하다는 뜻은 아니다. 검색 결과 0건은 '검색 결과 없음'으로 표시한다. 자료 누락으로 잔량을 알 수 없으면 상태도 '확인 불가'로 구분한다.

월 선택 시 잔량 기준을 선택 월의 조회 가능한 마지막 날짜로 삼는 안을 추천한다. 미마감 날짜를 포함할 경우 기록 기준 잠정 잔량임을 표시한다. 날짜별 판매·입고·실사의 선후는 Q07 결정이 필요하다. **파일:** 조회 결과만으로 재고 파일을 생성하지 않는다. 합계는 소진/점검 대상 품목 수만 가능하며 모든 재료의 g·ml·개를 한 수량으로 더하지 않는다.

**예외:** 가격 누락은 재료 수량 계산과 분리할 수 있지만 레시피 사용량 누락은 잔량을 미확정으로 만든다. 실사 전 과거 판매를 고치면 당시 장부 차이는 바뀔 수 있으나 이후 현재 잔량을 무조건 되돌리지 않는다. 오래된 실측 수량을 현재 실제 수량처럼 표시하지 않는다.

### F09. 저장·다시 사용

**사용자:** 각 등록창의 저장을 누르고 나중에 프로그램을 다시 연다. **처리 제안:** 한 변경에 필요한 기록 보관과 관련 결과 반영을 하나의 성공/실패로 처리한다. 입력칸 작성 중 값은 저장 버튼 전까지 임시값이다. 저장한 기록을 다시 열어 복원한다.

**화면:** 성공·실패·처리 중 상태를 표시한다. 저장되지 않은 변경을 저장 완료라고 안내하지 않는다. 재계산 결과가 이전 기록과 섞여 있으면 갱신 중임을 표시한다. **파일:** 앱 저장 방식은 Q10 미정이다. 기록 저장과 사용자가 내려받는 백업은 별개다. 매 저장마다 다운로드 파일을 만들지는 않는 안을 추천한다.

**예외:** 저장 공간 부족·사용 권한 문제·중단·손상은 원인과 재시도/백업 복원 안내를 표시한다. 손상된 저장 자료를 샘플로 자동 덮어쓰지 않는다. 저장 버튼 처리 중 종료가 발생했을 때 다음 실행에서 일부 저장 상태를 정상 완료로 취급하지 않는 안을 추천한다.

### F10. 전체 백업·복원

**사용자:** 공통 '백업·복원'을 누른다. 시안에는 창·복원 입력칸이 없으므로 필수 조작 보완이 필요하다.

**백업 제안:** 현재 성공적으로 저장된 기록 전체와 메뉴·재료·레시피·가격·영업달력·초기재고·월계획·자료정보 및 확정 운영 기준을 함께 내보낸다. 작성 중 임시값은 제외하고 그 사실을 알린다. 복원 가능 형식을 하나로 제한하는 안을 추천한다. JSON 형식과 생성시각·자료버전·매장 식별정보를 포함하는 안은 Q10 미정이다.

**화면·파일:** 백업 생성에 성공하면 별도 보관할 파일을 제공한다. 파일명에는 백업 시점을 구분할 수 있게 하는 안을 추천한다. 보고서용 엑셀과 혼동하지 않는다. 다운로드 중단·저장 실패는 백업 완료라고 표시하지 않는다.

**복원 제안:** 파일 선택 → 형식·버전·기록 연결 확인 → 백업 시점과 대상 확인 → 현재 전체 자료 교체 확인 → 성공 시 재계산 순서로 처리한다. 부분 복원·자료 병합은 하지 않는다. 취소하면 현재 기록을 유지한다. 불러온 합계만 신뢰하지 않고 보관 기록으로 결과를 다시 확인한다.

**예외:** 손상 파일·지원하지 않는 버전·없는 기준 자료·중복 식별번호·다른 매장 자료는 현재 자료를 바꾸지 않고 원인을 알리는 안을 추천한다. 초기 샘플 JSON을 사용자 백업과 동일한 파일이라고 자동 취급하지 않는다. 읽기 검증이나 저장이 실패하면 기존 자료를 유지한다. 복원 성공 후에는 복원 시점 이후의 현재 기록이 교체되므로 확인에 그 영향을 명시한다.

## 6. 계산 방법 제안

이 절은 전부 **미확정 제안**이다. 시안의 3.0%·2.2%나 예시 금액을 합의된 계산식으로 사용하지 않는다. 원본에 저장된 과거 값은 우선 보존하며 제안식과 차이가 나면 임의로 수정하지 않고 차이를 알린다.

| 계산번호 | 계산 방법 제안 | 적용·주의 사항 |
| --- | --- | --- |
| C01 순매출 | 판매수량 × 당시 실제 단가 − 기록 전체 할인액 | 금액은 부가세 제외. 할인은 1개당이 아닌 그 판매기록 전체 금액으로 제안한다. 기존 `net_sales`와 다르면 원본 불일치로 알린다. |
| C02 새 판매 개당 재료 원가 | 재료별로 '판매일에 적용되는 구매가격 ÷ 해당 구매용량 × 레시피 개당 사용량'을 구하고 합한다. | 적용시작일이 판매일 이하인 이력 중 가장 최근 기록. 같은 날짜 이력이 여러 개면 선택 불가. 구매용량 0·단위 불일치·가격 없음은 계산 불가. 채널이 비어 있는 레시피는 전체 적용, 포장 전용은 포장 판매에만 적용한다. 식재료와 포장재는 별도 표시한다. |
| C03 판매기록 전체 원가·수수료 | 원가 = 수량 × (보존된 개당 식재료 원가 + 보존된 개당 포장 원가). 수수료는 기록 전체 실제 금액을 사용한다. | 과거 원가를 현재 가격으로 다시 바꾸지 않는다. 수수료 자동 비율은 미정이며 빈 수수료를 0으로 간주하지 않는다. |
| C04 판매기록 수익성 | 남는 금액 = 순매출 − 전체 재료·포장 원가 − 전체 수수료. 수익률 = 남는 금액 ÷ 순매출 × 100 | 순매출 0이면 수익률 없음. 음수 이익은 손실로 표시하며 0으로 바꾸지 않는다. 임차료·인건비는 제외한다. |
| C05 메뉴·전체 합계 | 해당 기간 판매기록별 매출·수량·원가·수수료·남는 금액을 각각 합한다. 기간 수익률은 총 남는 금액 ÷ 총 순매출 × 100 | 개당 평균은 총액 ÷ 총수량. 개별 행 수익률을 단순 평균하지 않는다. 메뉴에 여러 가격이 있으면 실제 판매금액을 합산한다. 누락 행이 있으면 전체 이익은 미확정이다. |
| C06 기록 기준 매장 손익 | 총 순매출 − 총 판매 재료·포장 원가 − 총 결제수수료 − 해당 기간 비용기록 합계 | 월비용계획을 다시 더하지 않는다. 입고 구매대금을 판매 원가와 동시에 비용으로 더하지 않는다. 폐기·실사 차이 비용의 반영 여부는 Q08에서 별도 결정한다. |
| C07 비용 날짜 반영 | 원본 일별 비용은 해당 날짜 금액을 그대로 합한다. 새 비용은 사용자가 귀속일에 입력한 금액을 합하는 안을 추천한다. | 월비용 자동 분할은 1차 제외. 이미 배분된 기존 비용과 새 비용의 중복을 확인한다. 시안 월 총액 입력을 채택하려면 범위 재확인이 필요하다. |
| C08 재료 사용량·실사 없는 잔량 | 사용량 = 판매수량 × 채널에 맞는 레시피 개당 재료량. 잔량 = 초기재고 + 입고량 − 폐기량 − 판매 사용량 | 재료별 같은 기준단위로 계산한다. 원본 폐기는 음수 증감으로 보관돼 있으므로 음수값을 다시 빼서 재고를 늘리지 않는다. 신규 입력의 양수 폐기량과 원본 음수 증감을 구분한다. |
| C09 실사 있는 잔량 | 실사 당시 차이 = 실제 센 수량 − 해당 시점 장부 잔량. 이후 잔량은 실측량을 기준으로 이후 입고·폐기·판매 사용을 반영한다. | 실사 조정 차이를 더하는 방식과 실측량을 새 기준으로 삼는 방식을 동시에 적용하지 않는다. 마지막 실사 이전의 판매 수정은 실사 당시 차이를 다시 확인하되 현재 재고를 이중 증가시키지 않는다. 같은 날 순서는 Q07 미정이다. |
| C10 소진·음수 | 잔량 > 0이면 잔량 있음, = 0이면 소진, < 0이면 기록 점검 필요 | '안전재고 충족'·'충분'이라고 판단하지 않는다. 계산 근거 누락 시 별도 확인 불가 상태다. |
| C11 반올림 | 원가 계산 중 소수는 유지하고 화면 금액은 원 단위, 비율은 소수 첫째 자리로 표시하는 안을 추천한다. | 보관 정밀도·행별 반올림 시점·합계 기준은 Q11에서 결정한다. 화면에 반올림된 개당 원가를 다시 곱해 합계를 만들지 않는다. 합계와 세부 표시 차이의 안내가 필요할 수 있다. |

**가상 계산 예시:** 포장 라떼 10개, 당시 단가 4,800원, 전체 할인 1,000원, 개당 식재료 원가 1,000원·포장 원가 200원, 전체 실제 수수료 700원이라면 순매출 47,000원, 원가 12,000원, 메뉴에서 남는 금액 34,300원이다. 해당 기간 매장 비용이 5,000원이면 C06 기본안의 손익은 29,300원이다. 이는 원본 실적이 아니라 식을 설명하는 예시다.

**재고 예시:** 우유가 장부상 3,000ml지만 마감에 실제로 2,000ml를 셌다면 차이는 −1,000ml다. 다음날 입고 1,000ml, 판매 사용 400ml가 있으면 잔량은 2,600ml다. 실측량을 적용한 뒤 −1,000ml를 한 번 더 차감하지 않는다.

## 7. 검증할 연결 흐름과 예외

상세 제안 승인 후 검사 기준으로 사용할 목록이다. 새 기능을 위한 별도 검사 범위는 추가하지 않는다.

| 사례 | 기대 결과 |
| --- | --- |
| 정상 판매 한 건 저장 | 판매 목록 → 메뉴 수익성 → 매장 손익 → 관련 재료 잔량이 같은 기록으로 연결된다. |
| 판매 수량·할인 수정·판매 삭제 | 이전·새 기간의 결과가 갱신되고 사용량이 중복 반영되지 않는다. |
| 과거 가격 변경 없는 재접속 | 당시 원가·수수료 근거와 저장 기록이 유지된다. |
| 실사 전 판매를 나중에 수정 | 실사 당시 차이와 이후 잔량을 구분하고 실제 센 수량을 이중 반영하지 않는다. |
| 비용 입력·수정·삭제 | 귀속 기간 손익만 바뀌고 월계획과 이중 집계되지 않는다. |
| 입고·폐기·실사 0 기록 | 입고·폐기는 잘못된 값으로 처리하고 실사 0은 실제 소진으로 처리하는 제안을 검증한다. |
| 누락 수수료·원가·레시피 | 확정 수익이나 정상 재고로 숨기지 않는다. 영향받지 않은 값은 별도로 확인할 수 있다. |
| 미마감·빈 기간·범위 일부 | 0실적·전체 기간 완료로 표시하지 않고 실제 기록 구간을 알려준다. |
| 저장 실패·반복 클릭·취소 | 기존 기록 유지, 입력 유지, 중복 반영 없음, 성공 오표시 없음. |
| 백업 후 판매 변경하고 복원 | 백업 시점의 전체 기록·기준 자료·핵심 결과로 돌아간다. |
| 손상·잘못된 버전 백업 복원 | 현재 기록을 보존하고 실패 이유를 알린다. |

## 8. 결정 대기 목록

PRD 단계의 “모두 추천대로”는 계산식·화면·상세 동작을 확정하지 않는다고 명시돼 있다. 이번 FRD의 새 제안까지 자동 승인한 것으로 취급하지 않는다. 아래 항목을 순서대로 한 번에 하나씩 확인한다.

| 질문번호 | 정할 내용 | 추천 방향 — 미확정 |
| --- | --- | --- |
| Q01 | PRD와 시안의 1차 범위 차이 | PRD 유지. 시안의 확장 표시·버튼을 1차에서 제외하고 필수 기능 누락을 보완한다. |
| Q02 | 수수료·당시 실제 단가 입력 | 새 판매 수수료는 실제 금액 입력. 실제 단가를 확인·수정할 수 있게 한다. 비율을 임의로 고정하지 않는다. |
| Q03 | 누락 기준·과거 메뉴/날짜/채널 수정 | 근거가 없으면 저장 차단 또는 미완성 허용 중 선택. 의미가 바뀐 판매는 해당 판매일 기준을 다시 확인하고 단순 수량 수정은 보존한다. |
| Q04 | 새 날짜의 영업·마감 상태 | 미래 실적 저장 제한, 새 날짜 결과는 완료 여부 확인 전 잠정 표시. 마감 판단·조작은 별도 확인한다. |
| Q05 | 같은 날짜·메뉴·채널 판매 중복 | 기존 행 수정 안내. 자동 합산이나 덮어쓰기는 하지 않는 안. |
| Q06 | 새 비용의 입력 단위 | 1차는 귀속일별 금액 직접 기록. 월 자동 배분은 2차 유지. |
| Q07 | 같은 날 판매·입고·폐기·실사의 순서 | 실사를 하루 마감 후 수량으로 취급하는 안. 날짜밖에 없는 자료에서 장부·실사를 일관되게 비교하기 쉽다. |
| Q08 | 폐기·실사 차이의 손익 반영 | 1차에서는 수량 확인을 우선하고 손익에 별도 손실액을 추가하지 않는 안. 단, 손익에 폐기 손실이 포함되지 않는다는 한계를 명시한다. |
| Q09 | 재고 입력 상세 규칙 | 기준단위 사용, 입고·폐기 양수 입력, 실사 0 허용. 소수 자릿수·음수 발생 시 폐기 저장·공급사/사유 필수 여부는 확인한다. |
| Q10 | 저장·백업·복원 방식 | 저장한 전체 자료를 하나의 백업으로 보관·전체 교체 복원. 형식과 저장 환경은 구현 가능성과 함께 확인한다. |
| Q11 | 금액·비율 표시와 정밀도 | 중간 계산 소수 유지, 화면 원 단위·비율 소수 첫째 자리 표시. 보관·합계 반올림 기준을 확인한다. |

### 첫 번째 질문: 1차 기능은 PRD 범위를 그대로 유지할까?

| 선택지 | 쉬운 예시 | 추천 이유·영향 |
| --- | --- | --- |
| A. PRD 유지 — 추천 | 판매를 직접 입력하고 수익성·기록된 손익·재고를 확인한다. 시안의 월말 예상·자동 비용 배분·안전재고 예측·보고서 출력·시뮬레이션은 1차에서 제외한다. | 이미 합의한 4시간 핵심 흐름을 유지한다. 빠진 비용 수정·삭제와 백업·복원 조작은 보완한다. |
| B. 시안의 확장 기능도 1차로 재검토 | 월말 예상이나 월비용 자동 배분 같은 기능을 첫 버전부터 원한다. | 어떤 기능을 추가하고 기존 범위를 줄일지 다시 정해야 한다. 4시간 계획도 재검토한다. 이 선택만으로 전부 추가하지 않는다. |

선택 상태: 미정. 이 문서는 A를 기준으로 상세안을 제시했지만 사용자 선택 전까지 시안 수정이나 범위 변경을 확정하지 않는다.

## 9. 합의 기록

기존 PRD의 합의는 유지한다. 이번 FRD의 범위 차이 처리, 계산식, 상세 동작, 파일 형식은 아직 사용자 답변으로 확정되지 않았다. 답변을 받으면 관련 질문 상태와 기능·계산·오류 대응을 함께 갱신한다.
